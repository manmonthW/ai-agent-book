# 第11章　安全、权限、审批与审计

> 状态：Release Candidate 1  
> 核心原则：模型、检索内容、工具结果和Agent消息都是不可信输入；权力来自身份与政策，不来自文本。

## 本章回答的三个问题

1. Agent新增了哪些安全威胁？
2. 如何把高影响动作限制在准确授权和人工审批范围内？
3. 日志、不可变记录和密码学回执分别能证明什么？

## 5分钟速读

- Prompt Injection的核心风险是外部内容试图改变目标或诱导越权工具调用。
- 模型只能提出动作；身份、授权、政策和业务不变量由代码执行。
- 工具最小权限、读写分离，通用Shell/HTTP/SQL/文件系统必须沙箱化。
- 高影响动作先生成准确预览，审批绑定动作Digest、主体、期限和政策版本。
- 写操作幂等，防止Replay和网络重试造成重复副作用。
- RAG、Memory、网页和其他Agent消息都可能被污染，必须有来源与信任等级。
- Telemetry最少收集并脱敏，租户数据隔离。
- 密码学回执证明签名归属、内容完整性和链式顺序，不证明动作正确或政策实际执行。

## 一、威胁模型

| 威胁 | 路径 | 后果 |
|---|---|---|
| 指令操纵 | 用户、网页、邮件、文档 | 目标偏移、越权调用 |
| 关键系统访问 | 广泛文件/数据库/云权限 | 泄漏、篡改、破坏 |
| 资源过载 | 无限循环和高频工具 | 费用、拒绝服务 |
| 知识污染 | 恶意RAG或Memory内容 | 持久错误与注入 |
| 级联错误 | 未验证结果驱动后续写入 | 扩大影响 |
| Confused Deputy | 借Agent身份替攻击者操作 | 权限滥用 |
| Replay | 重放审批或请求 | 重复支付/发送 |
| 供应链 | 恶意工具、MCP Server、依赖 | 代码执行与数据外泄 |
| 多租户泄漏 | 检索、缓存、日志隔离失败 | 跨客户暴露 |

先绘制数据流：身份、秘密、信任边界、外部内容、工具、副作用和审计存储。

## 二、身份与授权

每次工具调用检查：

```text
谁（Principal）
对什么（Resource）
执行什么（Action）
为什么（Purpose/Run）
在什么条件下（Policy/Time/Tenant）
是否已批准（Exact Approval）
```

权限在工具执行时重新检查，不能只在会话开始时检查。Subagent继承最小必要权限，而非主Agent全部权限。

## 三、Prompt Injection防线

```text
外部内容可以影响模型知道什么
但不能改变模型被允许做什么
```

措施：

- 系统策略与外部数据分离；
- 来源、时间和信任标签；
- 工具调用后二次授权；
- 域名、路径、查询和输出限制；
- 秘密不直接进入模型上下文；
- 高影响动作审批；
- 注入攻击集和生产告警。

仅增加“忽略恶意指令”Prompt不构成可靠防线。

## 四、工具和沙箱

通用工具控制：

- 容器/虚拟机隔离；
- 只挂载必要路径；
- 默认禁网；
- 临时凭据和短期Token；
- CPU、内存、进程、时间、输出限制；
- 禁止访问宿主Socket和元数据服务；
- Artifact和依赖扫描。

高风险业务使用窄工具，参数明确、权限独立、写操作幂等、结果可查询。

## 五、准确载荷审批

模糊批准“帮我退款”不足以授权任意金额。审批对象：

```yaml
type: issue_refund
actor: user_456
order_id: order_789
amount: 128.00
currency: CNY
destination: original_payment_method
policy_version: refund-v7
expires_at: 2026-09-21T10:15:00Z
action_digest: sha256:...
```

执行前重新计算Digest。载荷、主体、政策或期限变化后重新审批。高风险场景可要求双人批准。

## 六、幂等、防重放与补偿

- 幂等键绑定业务对象和已批准Digest；
- 审批包含Nonce、期限和一次性状态；
- 重复请求返回原结果；
- 不可逆操作定义补偿或人工处置；
- 旧运行通过状态版本fencing拒绝写入。

幂等不等于撤销；它只防止同一逻辑操作重复发生。

## 七、数据、隐私与租户隔离

- 收集最少必要数据；
- 静态和传输加密；
- 索引前绑定租户与ACL；
- 检索前过滤权限；
- 日志、缓存和Artifact按租户隔离；
- 用户可查看、更正和删除Memory；
- 为数据和运行设置保留期；
- PII进入模型前按任务需要脱敏。

不要把秘密、访问Token和完整支付信息写入Trace。

## 八、多Agent安全

Agent间消息不自动可信。每个Agent有：

- 独立身份和权限；
- 明确任务范围；
- 输入输出Schema；
- 消息来源和签名/认证；
- 预算和生命周期；
- Artifact访问控制。

Manager不能通过委派绕过自身权限；Worker不能因消息声称“已批准”就执行高风险动作。

## 九、审计的三个层级

### 普通日志

适合调试，管理员可能修改。

### 不可变日志

只追加存储、保留策略和独立访问控制，提高篡改可见性。

### 密码学回执

对规范化事件签名，并用哈希链连接顺序。最小记录：Agent/工具身份、参数Hash、结果Hash、政策版本、时间、序号和前序Hash。

JCS（RFC 8785）可用于JSON规范化，Ed25519/EdDSA的标准描述见RFC 8032。私钥应位于Key Vault或HSM，回执只发布Key ID或公钥引用。

## 十、回执的能力边界

能证明：

- 某密钥签署了某内容；
- 内容自签署后未改变；
- 链中事件具有可检查顺序。

不能证明：

- 动作是正确选择；
- 政策实际执行；
- 输入真实；
- 密钥对应某个自然人的法律身份；
- 外部系统结果真实。

因此回执是审计基础，不是治理本身。

## 十一、安全测试

- 直接和间接提示注入；
- 知识库投毒；
- 路径穿越和任意网络访问；
- 权限提升和跨租户检索；
- 审批载荷篡改；
- Replay和重复副作用；
- 取消时悬挂操作；
- 工具输出过大和资源耗尽；
- 恶意MCP/A2A对端；
- 回执篡改和链断裂。

零攻击成功事件不能证明绝对安全；需要持续扩大攻击集、模型和环境覆盖。

## 十二、常见失败模式

| 失败 | 控制 |
|---|---|
| Prompt承担授权 | 代码策略网关 |
| 审批模糊意图 | 准确载荷Digest |
| 长期高权限凭据 | 短期、按任务凭据 |
| 先召回再过滤租户 | 检索前ACL |
| 日志即可信审计 | 不可变存储/签名回执 |
| 回执即合规 | 政策执行和验证器 |
| 子Agent继承全部权限 | 独立身份和最小授权 |

## 十三、检查清单

- [ ] 威胁模型覆盖身份、数据、工具和副作用。
- [ ] 模型不能决定授权。
- [ ] 外部内容不能扩大权限。
- [ ] 通用工具沙箱化。
- [ ] 高影响动作审批绑定准确载荷。
- [ ] 写操作幂等并防重放。
- [ ] 多租户检索、缓存、日志和Artifact隔离。
- [ ] Telemetry不泄露秘密和不必要PII。
- [ ] Agent间消息认证但仍按不可信输入处理。
- [ ] 回执能力边界表达准确。
- [ ] 安全攻击集进入离线和持续评估。
