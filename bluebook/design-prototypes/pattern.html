PATTERN 06 · RELIABILITY

幂等副作用

超时后先查询权威状态，而不是盲目重试支付、发送、删除或部署。

适用章节
06 · 09 · 11
主要风险
重复执行
复杂度
中
退出条件
纯只读

Context / Problem

Agent调用外部写工具时，网络可能超时，Worker可能重启。调用方不能仅凭超时判断动作是否已经发生。

Forces

业务正确性必须
恢复能力高
额外存储中
实现成本中

Solution

Checkpoint
Intent + Key→Execute
Idempotent→Persist
Result→Verify
Authority

Implementation sketch

existing = store.get(key)
if existing:
    assert digest(action) == existing.digest
    return existing.result

result = provider.execute(action, key)
store.put_once(key, digest(action), result)
return verifier.check(result)

Failure modes

随机生成重试键；相同键接受不同载荷；只记录请求而不读取最终状态；把幂等误认为可撤销。

Exit criteria

纯只读或数学计算没有外部副作用时，不需要业务幂等记录。

关键边界

幂等防止重复发生；补偿用于处理已经发生但需要纠正的动作。
