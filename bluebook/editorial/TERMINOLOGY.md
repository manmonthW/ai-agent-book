# 术语治理规范

## 权威定义原则

每个核心术语只指定一个主章节完整定义，其他位置引用，不重复创造近义定义。

| 术语 | 暂定权威位置 | 边界要求 |
|---|---|---|
| Agent | 第1章 | 必须包含环境反馈和行动选择；不等同普通聊天调用 |
| Model | 第1/3章 | 语义理解和策略决策，不负责最终授权 |
| Harness | 第9章 | 上下文、工具接口、状态、约束、验证和纠正 |
| Environment | 第1/3章 | Agent 外部的真实或仿真状态及转移规律 |
| Context | 第4章 | 当前模型调用可见的信息，不等于长期记忆 |
| Memory | 第5章 | 跨交互保留、可治理的信息 |
| RAG | 第5章 | 从外部知识源检索证据，不等同 Memory |
| Tool | 第6章 | Agent 感知或改变环境的受控接口 |
| Skill | 第4/6章 | 按需披露的知识与流程，不是硬权限边界 |
| Workflow | 第2/3章 | 步骤和转移主要由程序预定义 |
| Trajectory | 第3章 | 一次运行中的消息、决策、调用和观察序列 |
| Artifact | 第3/7章 | 持久中间或最终产物，不应全部塞入上下文 |
| Evaluation | 第10章 | 判断是否做对以及系统表现如何 |
| Observability | 第10章 | 让运行过程可见、可检索、可关联 |
| MCP | 第6章 | Agent/应用与工具、资源的互操作协议 |
| A2A | 第14章 | Agent 间任务和消息协作协议 |
| Multi-Agent | 第14章 | 独立上下文、身份或任务所有权的多个 Agent |

## 冲突处理

1. 记录原始定义和来源。
2. 判断是术语冲突、抽象层不同还是事实矛盾。
3. 在 `DECISIONS.md` 新建 ADR。
4. 更新 glossary 和 source map。
5. 不通过静默改写掩盖冲突。
