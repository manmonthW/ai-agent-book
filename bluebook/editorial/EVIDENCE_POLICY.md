# 证据政策

## 1. 证据等级

| 等级 | 定义 | 可支持的写法 |
|---|---|---|
| E0 | 作者观点、经验或待验证假设 | “本书建议”“可能” |
| E1 | 第三方文档、厂商案例或单一公开报告 | “某案例报告” |
| E2 | 仓库中存在代码，但未验证执行 | “提供实现示例” |
| E3 | Smoke Test 或最小端到端验证通过 | “基本路径可运行” |
| E4 | 可重复对照实验，有变量、指标和结果 | “在该实验条件下提升” |
| E5 | 多模型/多环境复现或多项独立研究一致 | 有限制条件的较强普遍结论 |

## 2. 必须进入 claims.yml 的内容

- 精确数字、比例、成本、延迟和 Benchmark；
- “提升”“降低”“优于”等因果或比较表述；
- 产品能力、上下文长度、发布日期等时效性事实；
- 安全、合规和法规相关断言；
- 对行业趋势的强判断。

## 3. 验证优先级

```text
最终环境状态/确定性验证器
→ 业务规则验证
→ 人工专家标签
→ 经校准的 LLM Judge
→ 未校准主观判断
```

LLM Judge 不得独立决定事实、权限、合规或高风险动作。

## 4. 实验报告最低字段

问题、假设、基线、变量、输入、环境、模型版本、指标、结果、失败、成本、证据路径和复现状态。

## 5. 语言约束

- E1/E2 不写成普遍因果结论。
- 单模型实验必须注明模型和日期。
- 厂商报告必须注明“厂商报告”而非中性事实。
- 无法核验的数字删除或改写为定性描述。
